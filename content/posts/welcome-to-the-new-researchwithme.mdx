ResearchWithMe is now a single-author blog. Every essay is an MDX file in this repository, rendered at
build time and published by pushing to main. There is no account system, no database, and no admin
panel — the writing is the site, and git is the only publishing interface.

<KeyTakeaways>

- One author, one archive: posts are written by me and published from git.
- Content is MDX, so prose can use figures, callouts, video, tables, and highlighted code.
- Everything is statically generated. There is no login, no database, and no runtime write path.

</KeyTakeaways>

## Why change what already worked?

The previous version was built to host many writers: applications, roles, an editorial dashboard, a
draft studio, and a moderation queue. For a blog written by one person, all of that was machinery
around the actual work. Removing it made the site smaller, faster, and considerably easier to reason
about.

What is left is the part that matters: a reading experience, a durable archive, and a publishing
workflow that is just git. The pages are pre-rendered with the Next.js App Router, so the essay text
is in the first response rather than assembled by a script in the browser
([Next.js docs](https://nextjs.org/docs/app)).

## How does publishing work now?

A post is one file:

```mdx
---
title: "A post about something"
description: "One or two sentences for cards, search, and the feed."
date: "2026-11-24"
tags: ["reproducible-research", "methodology"]
---

The body is MDX. Components are available without imports.
```

MDX is Markdown that compiles to JSX, which is why the prose can use a figure or a callout without a
bespoke page template ([MDX docs](https://mdxjs.com/docs/)). Add the file, commit it, push. The build
validates the frontmatter with Zod, renders the page, and updates the index
([Zod docs](https://zod.dev)). If a field is wrong, the build fails with the file name and the field —
no silently missing post.

<Callout tone="note" title="Drafts stay local">
  A post with <code>draft: true</code> appears when the site runs in development and is excluded from a
  production build. You can write in public view without publishing.
</Callout>

## What carried over from the old site?

The things that were worth keeping stayed: the typography, the paper-and-ink palette, the reading
progress bar, the theme control, and the archive-first navigation. Bookmarks, accounts, the studio,
and the research-network surfaces did not — they existed to support a multi-writer platform that is no
longer here.

If you are looking for something that used to be at a specific address, the [archive](/blog) and
[search](/search) are the places to start. The [RSS feed](/rss.xml) still works, and it is still the
best way to follow new writing. If you want the longer version of why this is a one-person site, the
[about page](/about) explains it.
