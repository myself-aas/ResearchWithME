# Browser test pass — 30 October 2026

Scope: the running production build of the root Next.js app, driven with Playwright against `http://localhost:3000`. Chromium was supplied by the sandbox (`QA_CHROMIUM_PATH`); the scripts live in `scripts/` and are documented in the README.

## What ran

| Script | Coverage |
| --- | --- |
| `scripts/qa_sweep.py` | 27 routes (public, studio, and the five auth pages) at 1280×800 and 390×844: HTTP status, title, `h1` count, duplicate ids, images without `alt`, links without an accessible name, axe-core WCAG 2.1 A/AA, horizontal overflow, console errors, and failed requests |
| `scripts/qa_flows.py` | 21 interaction checks: header/hero search, clear filters, category filter, like (and re-like), save, comment validation and posting, reading list, citation format switch and clipboard copy, empty submission, focus on the first invalid field, ORCID checksum rejection, assistant answer, mobile menu open/Escape/focus return |
| `scripts/qa_studio.py` | 9 checks: slug derived from the title, draft saved and published, review visible in the feed and at `/post/<slug>`, listed in `/dashboard/manage`, then deleted |

Results after the fixes below: **54/54 route loads clean** (no axe violations, no duplicate ids, no overflow, no console errors beyond the intentional 404 response), **21/21 flow checks**, **9/9 studio checks**.

## Defects found and fixed

1. **Duplicate `id="main-content"` on 13 routes.** `app/layout.tsx` wrapped every page in a div with that id while the page itself put it on `<main>`, so the skip link had two targets. The wrapper no longer owns the id; each page's `<main>` (including `PageState`, the studio shell, login, and the auth pages) is now the single target and is programmatically focusable.
2. **Two headings shared `id="catalogue-title"`** in `ArticleFeed` — "Browse by field" and "Latest reviews". The section now carries `aria-label="Reviews"` and the live-region heading uses `latest-title`.
3. **`aria-label` on a plain `<div>`** in `AuthorAvatar` (axe: `aria-prohibited-attr`). The illustrated avatar now declares `role="img"`.
4. **1.9:1 contrast in the studio's "Block type" control** (axe: `color-contrast`). MDXEditor styles its placeholder at `--baseBorderHover`; a scoped rule restores stone-700. The rule had to out-specify `._selectTrigger_[data-placeholder] > span:first-child`, which is also a (0,3,1) selector.
5. **Four requests for videos that do not exist.** Every review, the first edition, and one author profile requested an `.mp4` that was never rendered (404 per page view, plus a phantom "Video explainer" heading over an empty frame). `lib/video-manifest.json` is now generated from `public/videos` by `npm run videos:manifest` (run by `predev` and `prebuild`); `hasVideo()` gates the section, so the page simply omits it. The Marcus Vance profile gets its radar chart instead of a placeholder.
6. **404 pages used the site title.** `app/not-found.tsx` now exports `title: 'Page not found'` and `robots: { index: false }`.
7. **33 colored 2px left borders** on status callouts and alerts — a craft-floor violation ("colored border-left above 1px on cards, callouts, or alerts"). Callouts are now tinted rounded blocks; the two genuine quote bars dropped to 1px.
8. **The submission form's error summary sat next to the submit button** with no links, and `DESIGN.md` claimed it linked to fields. The summary now sits at the top of the form and lists each invalid field as a link that focuses it.

## Documentation corrected

- `docs/supabase-cms.md` claimed `@mdxeditor/editor` was not used and that the editor was custom-built. The editor is MDXEditor with a curated plugin/toolbar set; both the dependency row and the "deliberate departures" entry now say so.
- `DESIGN.md` described a monospace Markdown source editor with a write/preview pair; it now describes the MDXEditor surface that ships.
- The test counts in the audit report and the CMS guide matched neither state (26 and 51) and now read 55.

## Not covered

- Supabase-configured mode: the sandbox has no Supabase project, so auth, RLS, storage uploads, realtime, and the revalidate webhook ran only in local-demo mode.
- Rendered Impeccable detector: it needs a Chromium the CLI can find; the source detector ran as part of `npm run quality`.
- Screen readers and real input devices: axe and keyboard scripting stand in for both.
