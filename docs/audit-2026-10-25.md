## What was blocking or wrong

### P1 — Accessibility failures

- **Contrast:** footer/metadata text at 3.7:1 on stone-900, placeholder text at 2.4–2.6:1 on white and stone-50, and 2.6:1 labels on cards. Fixed by a contrast layer in `globals.css` that maps light-surface and dark-surface secondary text to AA values, by explicit placeholder colours, and by raising all `text-stone-400/500` usage on light surfaces to stone-600.
- **Unnamed form controls:** `select` and `textarea` elements had no accessible names (`/assistant`, `/author/[id]`, `/cite`, `/papers`, `/submit`, `/write`, `/author`). Every control now has a visible `<label>` or a specific `aria-label`; dynamic labels (for example per-takeaway inputs) are unique.
- **Heading order:** the author profile component emitted `h3` after an `h1`; the article page had no stable `h1` for screen-reader navigation. Headings are now ordered per route and the profile accepts a heading level.
- **Brand link name:** the logo link's `aria-label` did not contain its visible text; the label was removed so the accessible name comes from the wordmark, and the primary CTA label now includes the visible verb.

### P1 — Legibility and type system

- 46 findings for 10 px functional text and 27 for 11 px body text, plus 3 px vertical padding on small labels. All `text-[9px]/[10px]/[11px]` usages were raised to the 12 px token, `py-0.5` to `py-1`, and `px-1.5` to `px-2`, with the same rules enforced globally so future markup cannot regress.
- Guestimates of reading measure were replaced with real limits: prose is capped at 60–68ch, and the article body sits at a 65–75ch column.

### P1 — Reading flow and product truth

- A timed newsletter **pop-up** fired mid-article, contradicting the product's own "zero disruptive pop-ups" principle. It was removed; the newsletter is inline in the footer with an honest "stored in this browser" label.
- Two dead article modals, a dead paper modal, a dead writer modal, a dead submission modal, an identity modal, an assistant modal, a bookmarks drawer, a citation modal and three duplicate page-shell components were unused duplicates of the real routes. They were deleted so one implementation owns each task.
- Copy claimed live ORCID/GitHub OAuth, issued tracking IDs without recording anything, and reported PDF downloads that never happened. The verification page now states it is a local prototype, submissions are validated and persisted server-side with a real receipt, and PDF actions are honest browser print flows.

### P2 — Systemic visual issues

- **Kickers above headings** (2 instances) removed; headings now carry their own weight.
- **Nested cards** (23–26 instances) flattened into rules, spacing, and type on `/paper/[slug]`, `/papers`, `/editions`, `/editorial-board`, `/verify`, `/author/[id]` and the author card.
- **Icon-tile stacks** (7) replaced with inline icons or numbered editorial arguments on `/editorial-board` and `/verify`.
- **AI palette tell:** a purple gradient tile on the homepage category grid replaced with the archival stone/amber system; gradient washes are now single-hue scrims over local imagery.
- **Pulsing decorative dot** on `/assistant` removed; status is text plus icon.
- **Ghost cards:** the global `shadow-xs`/`shadow-2xs` now resolves to one low, offset shadow; heavy `shadow-xl/2xl` on static surfaces reduced to one elevation level.
- **Remote imagery:** `picsum.photos` thumbnails (a third-party dependency that failed in the sandbox) replaced with local editorial images; `next/image` now has `localPatterns` only.

### P2 — Responsive and interaction

- Mobile navigation was a horizontally scrolling strip with 10 destinations; it is now a proper disclosure menu with `aria-expanded`, `aria-controls`, Escape-to-close, focus return, and 44 px targets.
- Horizontal overflow at 320 px from the header cluster and article cards; fixed by sizing the logo responsively, collapsing the CTA to an icon, and adding `min-w-0`/`overflow-wrap` to feed cards and prose.
- Like/save/share actions had no failure path and allowed infinite re-likes; they now persist once, roll back on failure, and announce results in a live region.
- Destructive "clear reading list" is now a confirm-in-place action with a reversible choice.

### P2 — Robustness

- API routes now validate and bound every input, return JSON errors with correct status codes, reject non-JSON bodies, and rate-limit writes (`429` with `Retry-After`).
- `lib/db.ts` writes atomically (temp file + rename) and merges seed data instead of trusting a single file; a corrupted JSON file can no longer take down the archive.
- Newly published articles resolve immediately: the article route reads persisted data with `revalidate`, instead of only knowing build-time slugs (a real 404 reproduced during testing).
- The assistant matched on the whole query string, so a normal question ("what does the evidence say about…") always fell through to "no match". It now scores meaningful terms, ignoring stop words.
- Every form preserves input on failure, marks the first invalid field with `aria-invalid`, and moves focus to it.

### P3 — Polish

- Browser surfaces themed: amber selection and caret, 3 px focus rings with offsets, custom scrollbars, tabular numerals for data.
- One authored page entrance (360 ms, transform/opacity only) with a reduced-motion path that keeps state changes.
- Metadata completed: per-route titles and canonicals, Open Graph and Twitter cards, generated OG image, `sitemap.xml`, `robots.txt`, `manifest.webmanifest`, `app/icon.svg`, and security headers.
- Fonts self-hosted through `next/font/local` with generated fallback metrics — this removed a 0.185 CLS on the article page.

## Remaining recommendations

1. Replace the local identity prototype with real OAuth (Auth.js or similar) before claiming verification; keep the current copy until then.
2. Move JSON persistence to a database with per-record versioning; the current files suit a demo, not concurrent editorial work.
3. Add an end-to-end suite (Playwright) for publish, comment, and citation flows; the manual pass above is reproducible but not automated.
4. Consider a curated column-level editorial template for `/editions` once real PDF assets exist, rather than browser print.
