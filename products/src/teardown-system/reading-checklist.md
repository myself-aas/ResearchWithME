# Reading checklist

The Teardown System, Stages 2 and 5. Tick each item or write why it does not apply.

## Stage 2. Before running anything

- [ ] Commit hash, commit date, and clone date recorded
- [ ] README read in full; every promise copied into notes
- [ ] Top-level directories listed, each with a few words on what it holds
- [ ] Missing pieces noted: tests, licence, lock file, experiment configuration
- [ ] Entry points found and followed one file deep
- [ ] Dependencies: pinned, locked, containerised, or bare names
- [ ] Data path: where data comes from and where the split is decided (file, line)
- [ ] Evaluation path: where the reported metric is computed (file, line)
- [ ] Commit history read around the paper's date
- [ ] Code licence and data terms recorded
- [ ] One-page map of the repository drawn

## Stage 5. Reading the code against the claims

For each claim near the top of the ledger:

- [ ] Paper and code agree on hyperparameters, loss, preprocessing, architecture
- [ ] Documented command uses the settings reported in the paper, not other defaults
- [ ] No test data used in training, normalisation, early stopping, or tuning
- [ ] Metric computed the same way as for the baselines it is compared with
- [ ] Random seeds set and recorded
- [ ] Reported numbers are regenerated by the code, not read from a committed file
- [ ] No broad exception handlers, silent fallbacks, or uncounted skipped samples on the path to the result
- [ ] Every finding cites a file and line at the pinned commit
- [ ] Checks that found nothing are written down too
- [ ] No statement about the authors' intent anywhere in the notes
